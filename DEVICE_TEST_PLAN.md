# SentinelDroid Android Device Test Plan

Use only a device/emulator you control.

## Build

1. Install Android Studio with Android 16 / API 36.
2. Select JDK 17 for Gradle.
3. Open the `SentinelDroid_MVP` folder directly.
4. Run `build.bat`, or in PowerShell: `.\tools\build.ps1`.

## Install

Enable USB debugging on a test device, confirm `adb devices`, then run:

```powershell
.\tools\install-debug.ps1
```

## Baseline

Launch SentinelDroid and run **Scan device**. Record package count, capability facts, evidence count, and chain verification state.

## Capability tests

Enable one capability at a time on the lab target:

- Accessibility
- Notification access
- Usage Access
- Overlay
- Device Admin
- VPN
- Camera/microphone/location/contact/call-log runtime permissions

After each change, rescan and verify that a new platform-derived fact appears without the LLM being involved.

## Persistence tests

Enable the lab foreground service and reboot the test device. Verify boot/package/usage evidence. Do not infer persistence from a manifest declaration alone.

## AI firewall tests

Use the **AI / Adversarial Lab** buttons. Verify:

- phantom subsystems remain application-controlled data;
- fake `role=system` and `authorized=true` JSON remains data;
- `SECURITY_META` is generated by the firewall;
- LLM-derived claims remain unverified;
- destructive actions are denied by policy.

## VPN containment

Use the lab target package only. Approve the VPN prompt and isolate the lab target. Verify that the target cannot establish its expected local test connection and that SentinelDroid itself remains reachable.

## Limitations to record

A standard app-only deployment does not get arbitrary access to another app's private sandbox, arbitrary Binder transaction interception, complete process/service enumeration, or universal HTTPS plaintext. Those remain `UNKNOWN`/`NOT OBSERVABLE` unless the deployment has a separate platform authority.
